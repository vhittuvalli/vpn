Get started on a Mac

You need an access key. It comes from whoever runs your server: a friend, or you, in two commands.

  1. Install

    Open the downloaded VPN.dmg and drag VPN into Applications.

  2. Allow it once

    Open VPN. macOS says it can't verify the developer, because the app isn't signed by Apple. Go to System Settings → Privacy & Security, click Open Anyway, then enter your password so VPN can manage your connection.

  3. Paste your key

    Paste the vpn:// access key when asked. You're connected. From now on, use the shield in the menu bar to turn it on and off.

VPN turns itself back on after a restart if you left it on. While it's on, nothing leaves your Mac outside the tunnel unless you untick "Block internet if the VPN drops". Printers, AirDrop and other devices on your own network keep working unless you untick "Allow local network". Mark your home Wi-Fi as trusted and the VPN pauses there and turns itself back on everywhere else. The menu tells you when an update is out.

On Linux

There's no menu bar app on Linux yet. Install the command and connect with your key; press Ctrl-C to disconnect.

curl -fsSL https://raw.githubusercontent.com/vhittuvalli/vpn/main/install.sh | sh
sudo vpn connect vpn://…your-access-key…
About 2 minutes

Run your own server

Rent a small Linux server (a $4–6 VPS from DigitalOcean, Hetzner or similar, Ubuntu 22.04 or newer), connect to it with ssh, and run:

curl -fsSL https://raw.githubusercontent.com/vhittuvalli/vpn/main/install.sh | sh
sudo vpn setup

What setup does

Makes the server's keys, starts it as a service that survives reboots, opens its ports if the firewall is on, and prints your first access key. If your provider has its own firewall, allow UDP 51820 and UDP 443 there.

Sharing with others

sudo vpn invite alexnew access key for Alex sudo vpn deviceswho's online, and how much data each device has used sudo vpn revoke alexAlex's key stops working at once

Each person gets their own key. Their traffic leaves from your server's address, so only invite people you trust.

What's inside

Post-quantum end to end

ML-KEM-768 key exchange and ML-DSA-44 signatures layered on X25519. Traffic recorded today stays unreadable unless an attacker breaks both, and nobody can impersonate your server.

Looks like web browsing

Tick "Disguise as web traffic" and the tunnel runs inside HTTP/3 on port 443, using the same MASQUE framing as iCloud Private Relay.

No leaks when it drops

The kill switch blocks every route except the tunnel, IPv6 is blocked outright, and DNS goes through the VPN.

This is a learning project.

No one has audited it. Use it to learn how a modern VPN works or for your own experiments. If you need privacy you can rely on, use WireGuard.
