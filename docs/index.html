VPN

A menu bar VPN for the Mac, with post-quantum encryption, that connects to a server you run yourself.

I built this to learn how VPNs actually work. It started as a command line tool and turned into a small Mac app. The encryption follows WireGuard's design, with ML-KEM and ML-DSA layered on top, so traffic recorded today should stay private even once someone has a quantum computer.

There's no company and no account. You (or a friend) run the server, and every device gets its own access key.

Try it free for an hour

No server? Borrow mine. Get a guest key here, then paste it into the app (or sudo vpn connect on Linux). It works for one hour or 500 MB, whichever comes first. The demo has a fixed bandwidth budget each month; when it's used up, guest keys pause until the next month.

This is a demo server, so a few things to know. Your traffic leaves from my server in Bangalore, India, so websites will see an Indian IP address. Guests get about 5 Mbit/s, and outgoing email (port 25) is blocked. The server records when each guest key was issued and the IP address that asked for it, and while a key exists, when it connects and how much data it has used. It doesn't log which sites you visit.

Getting set up

  1. Open VPN.dmg and drag VPN into Applications.
  2. Open it. The app isn't signed by Apple, so macOS won't open it the first time. Go to System Settings → Privacy & Security and click Open Anyway. VPN then asks for your password once, to install the part that manages your network connection.
  3. Paste your access key. After that it's the shield in your menu bar.

Don't have a key? Someone running a server can make you one, or you can run your own.

What's in the menu

  • Turn it on and off, and see how long you've been connected, data each way, and ping.
  • Block internet if the VPN drops. On by default, so nothing slips out if the connection breaks.
  • Allow local network. Printers, AirDrop and your router keep working while you're connected.
  • Disguise as web traffic. For networks that block VPNs. The tunnel runs inside HTTP/3 on port 443.
  • Trust This Network. The VPN pauses on networks you trust, like home, and turns back on everywhere else.
  • A note in the menu when there's an update.

If it was on when you shut down, it reconnects on its own after you restart.

Running a server

Any small Linux server with a public IP works. I use the cheapest DigitalOcean droplet. SSH in and run:

curl -fsSL https://raw.githubusercontent.com/vhittuvalli/vpn/main/install.sh | sh
sudo vpn setup

That prints your first access key. To give someone else access, or take it away:

sudo vpn invite alex      # prints a key for Alex
sudo vpn devices          # who's online and how much data they've used
sudo vpn revoke alex      # Alex's key stops working right away

Devices can reach the internet through your server, but not each other. If your host has its own firewall, open UDP ports 51820 and 443.

Linux

There's no menu bar app for Linux yet. Install the command line version and connect with your key; Ctrl-C disconnects.

curl -fsSL https://raw.githubusercontent.com/vhittuvalli/vpn/main/install.sh | sh
sudo vpn connect vpn://your-access-key

Things to know

  • Nobody has audited this. I've tested and fuzzed it, but if you need privacy you can stake something on, use WireGuard or a VPN that has had a proper audit.
  • Websites see your server's IP instead of yours, but that IP leads back to whoever pays for the server.
  • One server means one location. Mac and Linux only for now, no phone apps yet.
