Free and open source · macOS and Linux

A VPN that stays private after quantum computers arrive.

Built like WireGuard, with ML-KEM-768 key exchange and ML-DSA-44 signatures layered on X25519, an optional HTTPS disguise on port 443, and a kill switch that blocks leaks.

Download Pick your system below.
Every download has a SHA-256 in checksums.txt.

Post-quantum end to end

Traffic recorded today stays unreadable unless an attacker breaks both X25519 and ML-KEM. Both sides sign the handshake, so breaking X25519 alone can't impersonate anyone.

Looks like web browsing

Switch to the HTTPS transport and the tunnel runs inside HTTP/3, using the same MASQUE framing as iCloud Private Relay. A browser visiting the server sees an ordinary page.

No leaks when it drops

The kill switch blocks every route except the tunnel, IPv6 is blocked outright, and DNS goes through the VPN to resolvers you pick.

This is a learning project.

No one has audited it. Use it to learn how a modern VPN works or for your own experiments. If you need privacy you can rely on, use WireGuard.

About 10 minutes

Set up your own server

You need a Linux server with a public IP address, such as a small VPS, and the Mac or Linux computer you downloaded to. vpn is a command-line app, so the rest happens in Terminal.

  1. Install what you downloadedyour computer

    cd ~/Downloads
tar -xzf vpn_*_darwin_*.tar.gz
xattr -dr com.apple.quarantine vpn_*_darwin_*/
sudo install -m 755 vpn_*_darwin_*/vpn /usr/local/bin/
vpn version

    The app isn't signed by Apple, so macOS quarantines it when it comes from a browser. The xattr line lifts that for this one download. If Safari already unpacked the file into a folder, skip the tar line.

    cd ~/Downloads
tar -xzf vpn_*_linux_*.tar.gz
sudo install -m 755 vpn_*_linux_*/vpn /usr/local/bin/
vpn version

  2. Install on the serverserver

    Connect to the server with ssh, then download the Linux build there.

    Most servers are x86-64. On an ARM server (uname -m prints aarch64), use the ARM64 build instead.

  3. Make a key pair on each machine

    umask 077
vpn genkey > private.key
vpn pubkey < private.key   # share this one with the other machine

    The private key never leaves the machine it was made on. Only the 88-character public key gets copied across.

  4. Write the config files

    Fill in the public details and copy the two commands. Run each one in the folder that holds that machine's private.key; the command reads the key from the file.

    The server listens on both either way.
    Shown after dev in ip route | grep default

    Only public keys go in here. Nothing you type on this page is sent anywhere.

    On the server
    On your computer

  5. Start the serverserver

    # open the VPN ports, keeping SSH reachable
sudo ufw allow 22/tcp && sudo ufw allow 51820/udp && sudo ufw allow 443/udp
sudo ufw --force enable

# run as a service that starts on boot
sudo mkdir -p /etc/vpn && sudo install -m 600 server.json /etc/vpn/
sudo install -m 644 vpn_*_linux_*/vpn.service /etc/systemd/system/
sudo systemctl enable --now vpn
journalctl -u vpn -n 5

    The log should end with listening on UDP 51820 and 1 peer(s). If your cloud provider has its own firewall, allow the same ports there too.

  6. Connectyour computer

    sudo vpn client -c client.json

# in another terminal
ping -c 3 10.8.0.1
curl -4 ifconfig.me   # prints your server's IP

    Press Ctrl-C to disconnect. Quit any other VPN first (Cloudflare WARP, a work VPN), since two VPNs fight over your routes. If the client ever exits without cleaning up, sudo vpn reset restores your normal network settings.
